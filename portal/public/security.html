EduBoard

Security overview

For a school's IT or data protection review · 28 September 2026

In short
  • The teacher's app keeps student data on the teacher's computer, not in a cloud. It can encrypt everything and lock itself.
  • The Portal holds only what the teacher publishes and what families add. It uses HTTPS only, hashed passwords, rate limits, and checks on every request that a family sees only their own children.
  • What isn't done yet is listed at the end: no code signing, no independent audit or certification, and no two-step sign-in so far.
What is kept, where and for how long is in the privacy notice; the commitments a school can sign are in the data processing terms.

1. The teacher's app

Where data lives A database file on the teacher's computer, and backups the teacher makes. There is no EduBoard account and no cloud copy.
Encryption With password protection on, the database and its backups are encrypted with a random 256-bit key (ChaCha20-Poly1305, SQLite3 Multiple Ciphers). That key is stored only encrypted (AES-256-GCM) under the teacher's password and under a recovery key, each stretched with scrypt; it is never stored in plain form.
Locking With password protection on, a lock screen at start and automatic locking after a set idle time (10 minutes unless the teacher changes it). Presenting mode shows only class screens and hides pages with private details while the screen is shown to a class.
Record of changes Every grade, attendance, enrolment and homework change is logged with when it happened. A removed student's entries are kept for 12 months, then deleted. A student can be erased completely, including from the Portal.
Network Only what the teacher sets up: publishing to the Portal (HTTPS), AI suggestions with the teacher's own key (sent only when the teacher asks), DingTalk or WeCom group posts, update checks, and an anonymous weekly count that is off unless turned on. Exit tickets stay on the classroom Wi-Fi. Files downloaded from the Portal are marked as coming from the internet, so the operating system checks them.
Updates From EduBoard's GitHub releases over HTTPS (relayed by the Portal where GitHub is blocked), with the file size checked. A backup is made before an update installs.

2. The Portal

Connections HTTPS only, with certificates from Let's Encrypt (Caddy). Browsers are told to use HTTPS for the site from then on (HSTS).
Passwords At least 8 characters, stored only as bcrypt hashes. A family changes their own password with the current one; a forgotten one is reset by the teacher, which signs the account out everywhere.
Sessions A signed cookie that scripts can't read (HttpOnly, Secure, SameSite=Lax), valid for 30 days, cancelled everywhere when the password changes or is reset.
Who sees what Checked on every request: a family sees only the children linked to their login, and only those children's classes. Each teacher publishes with their own sync secret and sees only their own classes. Sync and admin secrets are stored only as hashes, and a teacher's secret is shown once, when it's made.
Guessing and flooding Limits on sign-in attempts per address (50 in 15 minutes) and per username (10 failures in 15 minutes), on invite and QR links, on wrong secrets, on password changes and on AI use. Request sizes are limited before anything is read.
Uploaded files Checked by their contents, not their names: programs and Office documents with macros are refused, and only expected types are accepted (PDF, Office, images, text). Size limits: 20 MB for handed-in work, 25 MB for teachers' attachments, 10 MB for a report card.
Pages Nothing is loaded from other websites: no analytics, advertising, outside scripts or fonts. Pages can't be framed by other sites, links don't leak addresses (no referrer), and errors never show internal details, only a code and a reference.
AI keys The teacher's AI key for the Study Helper and translation stays on the server and is never sent to a browser.
Demo login The public demo (username demo) sees only a made-up class under its own teacher, and its password, email and QR logins can't be changed.

3. Running portal.edu-board.com

  • A server in Hong Kong (VPS.do). Only the Provider can sign in to it.
  • Updates are applied with a script that backs up the data first. Backups are kept on the same server; the oldest is deleted once there are 14.
  • If something goes wrong with a school's data, the school is told within 48 hours of the Provider finding out (see the data processing terms).
  • A school can run the Portal on its own server instead (it's open source), and then controls all of this itself, including where backups go.

4. Not done yet

  • Code signing. The Windows installer isn't signed yet, so Windows shows a warning the first time.
  • Independent review. No outside security audit or penetration test, and no certification (ISO 27001, SOC 2, or China's MLPS 等保) yet.
  • Two-step sign-in for the Portal.
  • Off-site backups for portal.edu-board.com: backups are on the same server for now.
  • EduBoard is made by one developer; there is no security team or on-call rota.

5. Reporting a problem

If you find a security problem, write to privacy@edu-board.com, or report it privately on GitHub, with what you found and how to see it. Please don't test against other people's accounts or data. You'll get an answer, and a fix as soon as it can be made.

安全概述

供学校 IT 或数据保护审查使用 · 2026 年 9 月 27 日

简要说明
  • 老师的应用把学生数据保存在老师自己的电脑上，而不是云端。它可以加密所有内容并自动锁定。
  • 学生门户只保存老师发布的内容和家长添加的内容。它只使用 HTTPS，密码以散列形式保存，限制请求次数，并在每次请求时检查家长只能看到自己的孩子。
  • 尚未完成的事项列在最后：目前还没有代码签名、没有独立审计或认证，也没有两步登录。
保存哪些内容、存放在哪里、保存多久，见隐私说明；学校可以签署的承诺见数据处理条款。

1. 老师的应用

数据存放 老师电脑上的一个数据库文件，以及老师自己做的备份。没有 EduBoard 账号，也没有云端副本。
加密 开启密码保护后，数据库及其备份使用随机生成的 256 位密钥加密（ChaCha20-Poly1305，SQLite3 Multiple Ciphers）。该密钥只以加密形式（AES-256-GCM）保存，分别由老师密码和恢复密钥经 scrypt 派生的密钥保护，从不以明文保存。
锁定 开启密码保护后，启动时显示锁定界面，闲置一段时间后自动锁定（默认 10 分钟，老师可以修改）。演示模式在向全班展示屏幕时只显示班级页面，隐藏含有私密信息的页面。
修改记录 每一次成绩、考勤、选课和作业的修改都会记录时间。已删除学生的记录保留 12 个月后删除。可以彻底删除一名学生，包括学生门户上的数据。
网络 只有老师设置过的连接：发布到学生门户（HTTPS）、使用老师自己密钥的 AI 建议（只在老师请求时发送）、钉钉或企业微信群消息、更新检查，以及默认关闭的匿名每周计数。出门条只在教室 Wi-Fi 中传输。从学生门户下载的文件会被标记为来自互联网，由操作系统检查。
更新 通过 HTTPS 从 EduBoard 的 GitHub 发布页获取（GitHub 无法访问时由学生门户转发），并检查文件大小。安装更新前会先做备份。

2. 学生门户

连接 只使用 HTTPS，证书来自 Let's Encrypt（Caddy）。浏览器此后会被要求始终使用 HTTPS 访问该网站（HSTS）。
密码 至少 8 个字符，只以 bcrypt 散列形式保存。家长凭当前密码自行修改；忘记密码时由老师重置，重置后该账号在所有设备上退出登录。
登录状态 一个脚本无法读取的签名 Cookie（HttpOnly、Secure、SameSite=Lax），有效期 30 天；修改或重置密码时在所有设备上失效。
谁能看到什么 每次请求都会检查：家长只能看到与其账号关联的孩子，以及这些孩子所在的班级。每位老师用自己的同步密钥发布，只能看到自己的班级。同步密钥和管理密钥只以散列形式保存，老师的密钥只在生成时显示一次。
防猜测和防刷 限制每个地址的登录尝试（15 分钟内 50 次）和每个用户名的失败次数（15 分钟内 10 次），并限制邀请链接和二维码链接、错误密钥、修改密码及 AI 使用的次数。请求在读取之前就限制大小。
上传文件 按文件内容而不是文件名检查：拒绝程序文件和带宏的 Office 文档，只接受预期的类型（PDF、Office、图片、文本）。大小限制：学生提交的作业 20 MB，老师的附件 25 MB，成绩单 10 MB。
页面 不从其他网站加载任何内容：没有统计分析、广告、外部脚本或字体。页面不能被其他网站嵌入，链接不会泄露地址（no-referrer），出错时不会显示内部细节，只显示代码和参考编号。
AI 密钥 老师用于学习助手和翻译的 AI 密钥保存在服务器上，从不发送到浏览器。
演示账号 公开的演示账号（用户名 demo）只能看到属于演示老师的虚构班级，其密码、邮箱和二维码登录都不能修改。

3. portal.edu-board.com 的运维

  • 服务器位于香港（VPS.do），只有服务方可以登录。
  • 通过先备份数据的脚本进行更新。备份保存在同一台服务器上，超过 14 份时删除最旧的一份。
  • 学校数据出现问题时，服务方会在发现后 48 小时内告知学校（见数据处理条款）。
  • 学校也可以在自己的服务器上运行学生门户（开源），这样以上所有事项都由学校自己掌控，包括备份存放在哪里。

4. 尚未完成

  • 代码签名。Windows 安装程序尚未签名，所以第一次运行时 Windows 会显示警告。
  • 独立审查。目前还没有外部安全审计或渗透测试，也没有认证（ISO 27001、SOC 2 或中国的等保）。
  • 学生门户的两步登录。
  • 异地备份：portal.edu-board.com 的备份目前保存在同一台服务器上。
  • EduBoard 由一位开发者制作，没有安全团队或值班安排。

5. 报告问题

如果你发现安全问题，请写信至 privacy@edu-board.com，或在 GitHub 上私下报告，说明你发现了什么以及如何复现。请不要用他人的账号或数据进行测试。你会收到答复，问题会尽快修复。
